# Совместимость Windows

| Целевая Windows | x86 | x64 |
|---|---|---|
| Windows 7 SP1 | Запуск и чтение конфигурации подтверждены пользователем в VMware, build 7601. Повторную проверку сборки пользователь подтвердил 25.11.2026. | NOT TESTED |
| Windows 8 | NOT TESTED | NOT TESTED |
| Windows 8.1 | NOT TESTED | NOT TESTED |
| Windows 10 | NOT TESTED | NOT TESTED |
| Windows 11 | Вне матрицы | PoC на Windows 11 Pro build 26300 с JRE x86 через WOW64 |

На рабочей станции Windows 11 Pro (build 26300) Maven 3.9.11 собрал агент с JDK 8u501 x64. Класс точки входа имеет bytecode 52. Один и тот же JAR с `--probe` запустился на Java 8u501 x64 и Java 8u221 x86. На Java 8u221 x86 проверены обычный запуск, ручное чтение, сохранение инвентарного номера с ведущими нулями и демонстрационный режим с карточками ОЗУ и дисками. В окне 820 × 700 обе кнопки видимы, регистрация заблокирована. Эти локальные runtime использованы только для проверки каркаса.

Java 8u221 x86 сообщает `Windows 10` в `os.name` на этой станции. Поле `os.arch` показывает архитектуру JVM. Источник семейства, сборки и архитектуры ОС предстоит проверить отдельно.

Локальный Emulator Suite проверен с Firebase CLI 15.37.0 и JDK 22. Маршрут Hosting вернул страницу SPA. Auth создал синтетического пользователя, которому Firestore запретил чтение и запись. Эта проверка не относится к публичному TLS из агента.

## Испытательный EXE

В сборке используется BellSoft Liberica JRE 8u514+5 i586. В матрице BellSoft Windows 7 SP1 указан для Liberica 8. Встроенный модуль LZMA SDK 26.06 x86 распаковывает комплект в пользовательский TEMP, запускает вложенный `javaw.exe` по абсолютному пути и ждёт закрытия окна. Манифест `asInvoker` нужен, поскольку Windows распознаёт стандартный модуль SFX как установщик. [Матрица BellSoft](https://bell-sw.com/pages/supported-configurations/) · [LZMA SDK](https://www.7-zip.org/sdk.html)

На Windows 11 x64 с Liberica x86 OSHI вернул архитектуру ОС 64-bit, процессор и плату. WMI показал 34 359 738 368 байт (32 GiB) установленной ОЗУ, 4 места по данным прошивки и 2 установленных модуля. Независимый запрос WMI подтвердил сумму. `Speed`, `ConfiguredClockSpeed` и `SMBIOSMemoryType` были доступны для обоих модулей. Найдены 1 видеоконтроллер, 2 кандидата во внутренние накопители и подключённый физический адаптер с `DHCPEnabled=False`. Адаптеры с PnP-префиксом `ROOT` исключены, поскольку некоторые виртуальные драйверы выставляют `PhysicalAdapter=True`.

На той же машине два экземпляра финального EXE одновременно открылись из локального SMB UNC под обычной учётной записью. Запись в исходную папку была запрещена ACL и проверена попыткой создать файл. Пути содержали пробелы и кириллицу. При пустом пути к установленной Java каждый экземпляр запустил вложенную JVM из собственного каталога TEMP. После закрытия окон оба каталога были удалены. Отдельно проверено чтение из окна Swing и сохранение номера с ведущими нулями.

По снимку Windows 7 SP1 x86 предыдущий EXE прочитал 2 GiB ОЗУ, VGA-адаптер, виртуальный SCSI-диск и DHCP. Расширенная WMI-проекция для памяти на Windows 7 оказалась недоступна. В новой сборке скорость читается напрямую из SMBIOS Type 17. Значения в MT/s показываются для SMBIOS 3.1+ при однозначном совпадении модуля по позиции, банку и ёмкости. На Windows 11 получено 3733 MT/s для обоих модулей. 25.11.2026 пользователь подтвердил работу новой сборки на Windows 7 SP1. В сообщении о повторной проверке отдельных показаний оборудования и номера сборки нет. [Windows API](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemfirmwaretable) · [Спецификация SMBIOS 3.1.1](https://www.dmtf.org/sites/default/files/standards/documents/DSP0134_3.1.1.pdf)

Начальная высота окна увеличена до 900 px и ограничена рабочей областью экрана. В демонстрационном окне 820 × 900 проверена видимость двух дисков и обеих кнопок без прокрутки.

На Windows 11 статический IPv4 прочитан на Java 8 x86 и сверен с WMI. Агент отображает адреса физических подключённых адаптеров с отключённым DHCP. Для поиска адресов используется системный индекс интерфейса. Диагностический вывод содержит только число адресов. [Документация Win32_NetworkAdapter](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-networkadapter)

Пробная реализация оставляет без значения VRAM и SSD/HDD, пока их источники не проверены. Пустые позиции отображаются только при наличии достоверных меток. Для коллектора предстоит проверить физический интерфейс и тип дисков, статические IPv4 на остальных целевых ОС, режим MIXED и топологию ОЗУ. Для завершения этапа 0 нужны проверки на целевых Windows, включая DPI, запуск из read-only UNC в целевой сети, TLS и синтетическую запись в разрешённый dev Firebase.
