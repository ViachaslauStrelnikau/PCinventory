# Резервная копия и восстановление Firestore на Spark

Команда сохраняет карточки ПК, исходные и проверенные отчёты, справочник и прежние названия расположений. Она читает все коллекции на один момент времени и записывает идентификаторы документов и значения Firestore, включая время, целые числа и вложенные поля. Ссылки карточек на отчёты сохраняются при переносе. Чтение и запись расходуют обычную квоту Firestore. [Бесплатная квота Firestore](https://firebase.google.com/docs/firestore/quotas) · [Чтение документов на заданный момент](https://firebase.google.com/docs/firestore/reference/rest/v1/projects.databases.documents/runQuery)

## В браузере

1. Войдите как администратор PCinventory. Откройте **«Настройки» → «Резервное копирование»** и нажмите **«Скачать резервную копию»**.
2. Для восстановления выберите файл копии. Интерфейс проверит контрольную сумму и покажет исходный проект и количество документов.
3. Введите Project ID отдельного проекта. Нажмите **«Войти через Google и проверить восстановление»** и выберите учётную запись с правами на целевой Firestore.
4. Проверьте целевой проект и число документов к созданию. Нажмите **«Восстановить в проект …»**. При расхождениях запись останавливается. Совпадающие документы остаются на месте.

Браузер и командная строка используют один формат файла. Скачивание доступно по роли администратора PCinventory. Запись при восстановлении использует краткосрочный токен Google OAuth и права Google Cloud IAM в целевом проекте. [Авторизация Firestore REST](https://firebase.google.com/docs/firestore/use-rest-api) · [Модель токенов Google в браузере](https://developers.google.com/identity/oauth2/web/guides/use-token-model)

### Настройка входа Google для восстановления

Создайте в Google Auth Platform OAuth-клиент типа **Web application**. Добавьте HTTPS-адрес веб-интерфейса в **Authorized JavaScript origins**, например `https://pc-inventory-9b119.web.app`. Настройте доступ операторов к OAuth-приложению и к области `https://www.googleapis.com/auth/datastore`. В режиме тестирования добавьте учётные записи операторов в тестовые пользователи. [Настройка Google Identity Services](https://developers.google.com/identity/oauth2/web/guides/get-google-api-clientid)

Запишите публичный Client ID в переменную `FIREBASE_RESTORE_OAUTH_CLIENT_ID` окружения `firebase` и запустите **Deploy Firebase**. Пока переменная отсутствует, веб-интерфейс позволяет проверить файл, а применить копию можно через командную строку. [Инструкция по развёртыванию](FIREBASE_DEPLOYMENT.md)

## Создать копию через командную строку

Нужны Node.js 24 и Google Cloud CLI. Войдите через `gcloud auth login` под учётной записью с правом читать документы исходного проекта. Веб-роль «Администратор» служит для работы в реестре. Команда копирования использует права Google Cloud IAM. [Права Firestore в Google Cloud](https://cloud.google.com/firestore/native/docs/security/iam)

В PowerShell из корня репозитория задайте путь к новому файлу в существующей защищённой папке.

```powershell
$copy = 'D:\SecureBackups\pcinventory-2026-11-26.pcinventory-backup.json'
node tools/firestore-backup.mjs backup --project pc-inventory-9b119 --file $copy
```

Команда выводит время снимка и количество документов по коллекциям. Файл содержит данные реестра, в том числе учётные поля сотрудников, если они заполнены. Храните его в папке с ограниченным доступом вне репозитория. Один файл соответствует одному снимку.

## Восстановить в другом проекте

Подготовьте отдельный проект с базой Firestore `(default)` и оставьте приём отчётов закрытым на время восстановления. Учётной записи оператора нужны права чтения и создания документов в целевом проекте. Укажите его Project ID явно.

```powershell
$target = 'your-test-project-id'
node tools/firestore-backup.mjs restore --project $target --file $copy
```

Первая команда проверяет контрольную сумму и показывает количество документов к созданию. После проверки цели и плана выполните запись.

```powershell
node tools/firestore-backup.mjs restore --project $target --file $copy --apply
```

Восстановление создаёт отсутствующие документы и сверяет результат с копией. При сбое повторите проверку плана с тем же файлом. Совпадающие документы будут пропущены, а расхождение в любой из четырёх коллекций остановит запись. Скопированные данные можно проверить в Firestore Console. Чтобы открыть их в приложении, разверните сайт и правила целевого проекта и настройте доступ. Учётные записи Firebase Authentication, роли, настройки приёма, правила и индексы настраиваются отдельно. Идентификаторы авторов и время событий остаются в истории. [Развёртывание нового проекта](FIREBASE_DEPLOYMENT.md)

## Локальная проверка

```powershell
npm --prefix tests/rules run test:backup
```

Тест создаёт два отдельных проекта в Firestore Emulator и заполняет их синтетическими данными.
