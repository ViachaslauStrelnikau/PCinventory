# Веб-интерфейс инвентаризации

Макеты в каталоге `design/frontend/` задают общий вид интерфейса. Состав экранов и действия определяются сценариями и правами роли.

## Роли

| Возможность | Администратор | Пользователь |
|---|---|---|
| Реестр и карточки компьютеров | Просмотр и поиск | Просмотр и поиск |
| Статистика и отчёты по реестру | Да | Да |
| Создание, редактирование, архивация, восстановление и удаление из архива | Да | — |
| Просмотр, исправление, принятие и отклонение входящих отчётов | Да | — |
| Управление приёмом отчётов | Да | — |
| Управление веб-учётными записями | Да | — |
| Смена собственного пароля | Да | Да |
| Редактирование справочника расположений | Да | — |

Обе веб-роли получают данные только после входа. Пользователь составляет отчёты по карточкам реестра и может экспортировать текущую выборку в XLSX. Сборщик Windows сохраняет отдельную роль `COLLECTOR` со своим сценарием отправки. Интерфейс показывает действия по роли, а правила Firestore проверяют право на каждый запрос.

## Экраны

- **Реестр.** Поиск, фильтры, выбор колонок, сортировка и постраничный просмотр. Дерево «Здание → Этаж → Кабинет» строится из карточек. Фильтр по зданию включает все его этажи и кабинеты. Поиск и остальные фильтры действуют вместе с деревом. Для администратора здесь доступны создание карточки и управление архивом.
- **Карточка ПК.** Отдельная страница с учётными данными, конфигурацией, модулями ОЗУ и накопителями. Администратор может создать карточку вручную, отредактировать данные и отправить карточку в архив. В архиве администратор может восстановить карточку или окончательно удалить её после отдельного подтверждения. Пользователь открывает карточку для просмотра.
- **Входящие отчёты.** Экран администратора с вкладками «Ожидают проверки» и «Обработанные». В повторном отчёте рядом показаны текущие и предложенные значения. Пока отчёт ожидает проверки, администратор может исправить учётные данные и характеристики оборудования. Исходные данные агента сохраняются вместе с исправлениями и отметкой о том, кто и когда их внёс. Здание, этаж и кабинет подтверждаются единым блоком. Необязательные учётные поля применяются выборочно. Если поле пропущено, сохраняется текущее значение. Принятие записывает карточку с подтверждёнными значениями и итог проверки одной транзакцией.
- **Статистика.** Переключение между всеми активными ПК и текущей выборкой реестра. Неизвестные значения показываются отдельно. Итоги, графики и выгрузки доступны обеим веб-ролям.
- **Справочники.** Администратор добавляет и переименовывает здания, этажи и кабинеты в дереве расположений. Здание и этаж можно добавить до появления кабинетов и ПК. Удаление требует подтверждения и доступно для записей без вложенных элементов и связанных карточек, включая архивные. При переименовании все связанные карточки получают новое расположение. Если в ожидающем отчёте использовано переименованное или удалённое расположение, администратор исправляет его перед принятием. Исходные отчёты сохраняются.
- **Настройки.** Обе роли могут сменить собственный пароль, повторно указав текущий пароль и дважды введя новый. Администратор дополнительно управляет приёмом отчётов. Администратор скачивает резервную копию и проверяет файл перед восстановлением в отдельном проекте. Для записи требуется отдельный вход Google с правами целевого Firestore. [Резервное копирование](FIRESTORE_BACKUP.md)
- **Пользователи.** Сотрудник регистрируется со страницы входа, подтверждает почту и отправляет запрос при входе. Администратор одобряет запрос, меняет имя и роль, деактивирует и восстанавливает доступ. В разделе доступны роли «Администратор» и «Пользователь». Последнего активного администратора защищает сервер, включая параллельные изменения. Удаление веб-учётных записей запрещено. [Инструкция по доступу](USER_ACCESS.md)

Обе формы показывают требования к паролю. Допускается от 8 до 128 символов, включая как минимум одну строчную букву, одну прописную букву и одну цифру.

Перед подключением новых операций обновляются контракт данных и правила доступа. В эмуляторе проверяются права пользователя, ручное создание карточки, исправления администратора, принятие исправленного отчёта и окончательное удаление только из архива. Действующие ограничения описаны в [SECURITY.md](SECURITY.md).
