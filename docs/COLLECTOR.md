# Коллектор конфигурации

`HardwareSource` возвращает снимок оборудования. `WindowsHardwareSource` читает локальные OSHI, WMI и SMBIOS, `HardwareNormalization` обрабатывает значения и противоречия. Окно читает снимок в фоновом потоке после нажатия «Прочитать конфигурацию».

| Данные | Источник и ограничения |
|---|---|
| CPU, плата, компьютер и ОС | OSHI. Исходное имя CPU сохранено отдельно. Из отображаемой модели удаляются товарные знаки и суффикс частоты. Из WMI также считывается название редакции Windows. |
| ОЗУ | WMI перечисляет модули и места в массивах системной памяти. SMBIOS Type 17 дополняет тип, форм-фактор и скорость при однозначном совпадении ёмкости, позиции и банка. Скорость показывается в MT/s с SMBIOS 3.1. Сначала используется настроенная скорость, затем номинальная. |
| Слоты ОЗУ | Явные пустые позиции добавляются при подтверждённой топологии и надёжной маркировке. При согласованных показаниях можно вывести число свободных разъёмов без их названий. При расхождении источников или неясном форм-факторе число свободных разъёмов остаётся неизвестным. |
| GPU | WMI возвращает все видеоконтроллеры, модель и производителя при наличии. VRAM остаётся неизвестной до проверки надёжного источника. |
| Диски | `Win32_DiskDrive` перечисляет физические диски. `MSFT_PhysicalDisk` уточняет ёмкость, интерфейс и тип SSD/HDD при уникальном совпадении серийного номера в обоих списках. На Windows 7 и при недоступности или неоднозначности источника тип остаётся `UNKNOWN`. Серийные номера дисков не входят в снимок или диагностику. |
| Сеть | WMI сопоставляет подключённые физические адаптеры и настройки IPv4. Только для адаптеров с отключённым DHCP Java читает IPv4 по системному индексу интерфейса. Поддерживаются режимы `DHCP`, `STATIC`, `MIXED` и `UNKNOWN`. |
| Идентификатор | UUID компьютера из `Win32_ComputerSystemProduct` либо случайный UUID профиля при заглушке или недоступности источника. Выбранный идентификатор закрепляется в `%LOCALAPPDATA%/ComputerInventory/device-id`. Повторные запуски используют тот же файл. Повреждённый файл сохраняется, а окно показывает предупреждение. |

[Документация OSHI](https://github.com/oshi/oshi) · [Память WMI](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-physicalmemory) · [MSFT_PhysicalDisk](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/msft-physicaldisk) · [Win32_ComputerSystemProduct](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-computersystemproduct)

## Проверка

- 9 тестов Maven покрывают нормализацию CPU, четыре сетевых режима и фильтрацию IPv4, типы дисков, подтверждённые и неопределённые слоты ОЗУ, скорость из старого SMBIOS, постоянство и обработку ошибок файла идентификатора.
- Windows 11 x64 build 26300, Liberica Java 8u514 x86 через WOW64. Сверка с WMI подтвердила 12 ядер и 24 потока, 32 GiB установленной DDR4, два модуля по 3733 MT/s, один видеоконтроллер, два NVMe SSD и режим STATIC. Из трёх дисков, видимых системе, внешний USB-диск исключён. Число свободных разъёмов осталось неизвестным из-за сведений о форм-факторе в таблице прошивки.
- SMBIOS-идентификатор сохранился между отдельными запусками диагностики. Диагностика выводит источник идентификатора и количество статических IPv4.
- Проверены контрольная сумма свежего EXE, открытие окна на комплектной JVM и удаление временной распаковки после штатного закрытия.
- Для последующей проверки на оборудовании остаются свежая сборка на Windows 7 SP1, режим MIXED с двумя физическими адаптерами и совпадения UUID на клонированных ПК.

[Примеры синтетических отчётов](examples/collector-reports.json) иллюстрируют полный и частичный сбор. Формат JSON для передачи предстоит утвердить на этапе контракта.
