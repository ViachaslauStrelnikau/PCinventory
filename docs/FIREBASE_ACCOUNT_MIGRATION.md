# Передача Firebase-проекта другому Google-аккаунту

Эта инструкция подходит для передачи проекта `pc-inventory-9b119` на обычный Google-аккаунт, который компания использует для работы. Передача выполняется через роль владельца существующего проекта. Сохраняются Project ID, адрес сайта, данные Firestore, учётные записи Firebase Authentication и привязка выпущенных Windows-агентов.

## 1. Добавить нового владельца

1. Убедитесь, что компания контролирует рабочий аккаунт и может восстановить к нему доступ.
2. Войдите в Google Cloud Console под текущим владельцем. Выберите проект `pc-inventory-9b119`, откройте **IAM и администрирование → IAM → Предоставить доступ** (**Grant access**).
3. Укажите адрес рабочего Google-аккаунта, назначьте роль **Owner** (`roles/owner`) и сохраните.
4. Войдите под новым аккаунтом и примите приглашение из письма Google. Откройте Firebase Console, примите условия Firebase, если появится запрос, и убедитесь, что новый аккаунт указан как **Owner** в настройках проекта **Пользователи и разрешения**. [Приглашение владельца](https://docs.cloud.google.com/iam/docs/granting-changing-revoking-access) · [Роли Firebase](https://firebase.google.com/docs/projects/iam/roles-basic)

## 2. Передать доступ к рабочим операциям

- **Администрирование реестра.** Если новый оператор будет работать в PCinventory, зарегистрируйте его рабочую почту и одобрите запрос с ролью **«Администратор»**. Это отдельная роль приложения. Проверьте вход, доступ к очереди отчётов, пользователям и резервному копированию. [Выдача доступа к PCinventory](USER_ACCESS.md)
- **Восстановление из копии.** Если новый оператор будет восстанавливать данные, добавьте его Google-аккаунт в **Google Auth Platform → Audience → Test users**, пока OAuth-приложение в режиме **Testing**. Если в Branding или Contact Information указан прежний личный адрес, обновите контактные данные. Проверьте авторизацию Google и предпросмотр восстановления синтетической копии в отдельном проекте Spark, к которому у оператора есть права Firestore. [Настройка OAuth для восстановления](FIRESTORE_BACKUP.md#настройка-входа-google-для-восстановления)
- **Развёртывание сайта.** Отдельно выдайте новому оператору доступ к репозиторию GitHub, если он будет запускать **Deploy Firebase**. Workflow использует сервисную учётную запись Google Cloud через Workload Identity Federation. Если меняется владелец репозитория, обновите условия OIDC для нового владельца и пути workflow. [Настройка развёртывания](FIREBASE_DEPLOYMENT.md#подготовка-ручной-github-action)

## 3. Проверить передачу

Убедитесь, что новый владелец видит Hosting, Firestore и Authentication в Firebase Console и что у проекта отключён биллинг, чтобы сохранить тариф Spark. После проверки необходимых рабочих операций решите, сохранить прежнему аккаунту резервный доступ или отозвать его. При отзыве проверьте доступы отдельно в Google Cloud IAM, PCinventory, тестовой аудитории OAuth и GitHub.

Если нужен новый **Project ID**, используйте [порядок переезда в новый Firebase-проект](FIREBASE_DEPLOYMENT.md#обновления-и-переезд).
